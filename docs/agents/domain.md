# Domain docs

Use a single-context layout: root `CONTEXT.md` and `docs/adr/`.

Before exploring, read `CONTEXT.md` and ADRs relevant to the area of work
when present. If these files are absent, proceed silently; the domain-modeling
skill creates them as terminology and decisions are resolved.

Use the glossary's vocabulary in issue titles, proposals, hypotheses, and tests.
Note genuine vocabulary gaps for domain-modeling. Explicitly flag conflicts
with an existing ADR rather than silently overriding its decision.
